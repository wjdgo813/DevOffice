# DevOffice

**비개발자가 대화만으로 웹·앱 제품을 만드는 Claude Code 플러그인.**

코드를 대신 써주는 도구가 아니라, **개발 조직 하나를 붙여주는** 도구입니다.
기획자가 PRD를 쓰고, 기술 총괄이 설계하고, 개발자가 만들고, 확인을 받고 배포합니다.
사용자는 **무엇을 만들고 싶은지만** 말하면 됩니다.

> ⚠️ **v0.1 개발 중입니다.** 아직 실사용 검증 전이라 동작이 바뀔 수 있습니다.

---

## 설치

Claude Code에서:

```
/plugin marketplace add wjdgo813/DevOffice
/plugin install devoffice@devoffice
```

## 시작

제품을 만들 빈 폴더에서 Claude Code를 열면 **알아서 말을 겁니다.**
명령어를 외울 필요 없습니다.

```
안녕하세요. 어떤 걸 만들고 싶으세요? 한 문장이면 충분해요.

  예) "동네 사람들끼리 물건 빌려주는 사이트"
      "우리 동아리 일정 관리하는 앱"
```

## 어떻게 동작하나

```
아이디어 → 제품 정의 → 이름 → 기술 결정 → 준비물 → 첫 화면 배포
                                                      ↓
                        ┌───────── 기능 하나씩 ─────────┐
                        │  명세 → 계약 → 구현 → 확인 → 배포  │
                        └──────────────────────────────┘
```

**한 번에 하나씩만 만듭니다.** 사용자가 눈으로 확인하기 전에는 다음 기능이
기계적으로 차단됩니다. 한꺼번에 만들면 어디가 잘못됐는지 찾을 수 없기 때문입니다.

### 설계 원칙

| | |
|---|---|
| **파일이 조직의 기억** | 에이전트는 매번 기억상실 상태로 출근한다. 디스크만 남는다 |
| **계약은 컴파일된다** | API 규약을 문서가 아니라 타입으로 쓴다. 위반이 빌드 실패로 잡힌다 |
| **화면을 승인한다** | 완료의 정의는 테스트 통과가 아니라 "사용자가 눌러보고 됐다고 한 것" |
| **한 번에 하나씩** | 배려가 아니라 품질 장치. 많이 만들면 사람도 AI도 누락한다 |
| **막히면 멈춘다** | 추측해서 진행하지 않는다. 비개발자는 잘못된 추측을 알아채지 못한다 |
| **되돌릴 수 있다** | git을 가르치지 않는다. 사용자는 "되돌려줘"만 안다 |

## 기여

가장 도움이 되는 기여는 **스택 프리셋**입니다.
`templates/scaffold/` 에 프리셋을 추가하면 새로운 조합을 지원할 수 있습니다.

버그 제보 시 `.devoffice/journal.jsonl` 을 함께 올려주시면
어느 단계에서 막혔는지 정확히 알 수 있습니다.
