# 기능 구체화 — 어떻게 보일지 함께 정한다

**이 단계의 목적은 빈칸 채우기가 아니라 "화면을 함께 그리는 것"이다.**

사용자는 "잔액 조회 기능"이라고 말할 수 있다.
하지만 **그게 화면에서 어떤 모습이어야 하는지는 모른다.**

- 우리가 가정하면 → 틀린다
- 그냥 물으면 → "잘 모르겠어요"
- **구체적인 것을 보여주면 → 고를 수 있다**

> 비개발자는 추상적 요구를 판단하지 못하지만 **눈앞의 구체물에는 "이거 아니에요"를 정확히 말한다.**

---

## 1. 먼저 사용자 머릿속을 본다

**리서치부터 하지 마라.** 사용자가 이미 그림을 갖고 있을 수 있다.
Formula-Q 처럼 사용자가 그 도메인을 잘 아는 경우가 실제로 많다.

```
잔액 화면, 머릿속에 그려두신 게 있으세요?

 ① 있어요 — 말씀해주시면 그대로 만들게요
 ② 대충은 있는데 정리가 안 돼요
 ③ 잘 모르겠어요 — 보통 어떻게 하는지 찾아봐 주세요
```

| 답 | 다음 |
|---|---|
| ① | 듣고 **스케치로 되말한다**(§3) → 리서치로 **빠진 것만 보완**(§2) |
| ② | 아는 부분을 듣고 → 리서치로 나머지를 채운다 |
| ③ | 리서치 → 선택지 제시(§4) |

**①이어도 리서치를 완전히 건너뛰지 않는다.** 사용자 안에 빠진 게 있을 수 있고,
그건 "이런 것도 보통 같이 보여줘요"로 **덧붙이면** 된다. 대체하려 들지 마라.

## 2. 리서치 — 언제, 무엇을

### 언제 하나

매번 하면 기능당 5분씩 낭비다. **화면을 상상할 수 있는지**로 판단한다.

| | 예 | 리서치 |
|---|---|---|
| 🟢 관행이 뻔하다 | 로그인, 검색창, 목록, 설정 | **안 한다** |
| 🟡 도메인 관행이 있을 것 같다 | 잔액·수익률 표시, 차트, 주문 화면 | **한다** |
| 🔴 완전히 새롭다 | 전략 조립 화면 | 한다 + 껍데기 먼저 |

**"주식 앱의 잔액 화면"은 🟡이다.** 관행이 분명히 있고, 그걸 따르면
사용자가 처음 봐도 익숙하다. 우리가 새로 발명할 이유가 없다.

### 무엇을 조사하나

`research` 에이전트에게 **도메인 관행 모드**로 요청한다.

```
[도메인 관행 조사]
기능: 주식 자동매매 앱의 잔액·수익 화면
알고 싶은 것:
  · 어떤 정보를 보여주나 (항목)
  · 숫자만인가, 그래프도인가
  · 기간 선택이 있나. 기본값은
  · 흔히 빠뜨려서 문제가 되는 것
근거: 실제 앱 이름을 최소 3개 들 것
```

**"대부분", "보통"이라고 쓰려면 사례 3개 이상이 있어야 한다.**
하나 보고 일반화하면 그건 조사가 아니라 인상이다.

## 3. 스케치로 되말한다 — 말보다 그림

**텍스트 스케치가 이 단계에서 가장 강력한 도구다.**
껍데기를 만들려면 10분이지만 스케치는 즉시 나온다.

```
말씀하신 걸 이렇게 이해했어요.

  ┌──────────────────────────┐
  │  총 평가금액              │
  │  12,340,000 원           │
  │  +340,000 (+2.83%)  ▲    │
  ├──────────────────────────┤
  │  [1주] [1달] [3달] [1년]  │
  │                          │
  │      ╱╲    ╱─────        │
  │    ╱   ╲╱                │
  │  ╱                       │
  ├──────────────────────────┤
  │  삼성전자    +5.2%  ▲     │
  │  SK하이닉스  -1.1%  ▼     │
  └──────────────────────────┘

맞나요? 다르면 어디가 다른지 말씀해주세요.
```

- 폰 화면이면 **세로로 좁게** 그린다. 실제 비율이 보여야 판단이 된다
- 숫자는 **그럴듯한 실제 값**을 넣는다. `{금액}` 은 판단할 수 없다
- 색·폰트는 그리지 않는다. **무엇이 어디에 있는지**만

## 4. 선택지로 제시한다 — 조사 결과를 쏟지 마라

리서치 결과를 그대로 보여주면 비개발자는 읽지 않는다.
**2~3개 안으로 압축하고, 각각에 스케치·소요시간·트레이드오프를 붙인다.**

```
잔액 화면은 보통 이 세 가지 중 하나예요.

 ① 숫자만 (20분)
    ┌────────────────┐
    │ 12,340,000 원  │
    │ +340,000(+2.8%)│
    └────────────────┘
    빠르게 확인하기 좋아요. 지금 얼마인지만 보면 될 때.

 ② 숫자 + 그래프 (35분)                            ← 추천
    위에 숫자, 아래에 기간별 그래프
    "언제부터 잘 되고 있나"가 보여요.
    전략을 비교하실 거라 이게 맞을 것 같아요.

 ③ 숫자 + 그래프 + 종목별 (50분)
    ②에 종목별 수익률까지
    가장 자세하지만 폰 화면이 빽빽해져요.
    종목이 10개 넘어가면 스크롤이 길어집니다.

 ※ 나중에 ①에서 ②로 올리는 건 쉬워요. 반대도 되고요.
```

**추천에 이유를 붙인다.** "추천"만 있으면 근거 없는 강요다.
그리고 **사용자 상황에 맞춘 이유**여야 한다 — "전략을 비교하실 거라".

### 조사에서 나온 "흔한 함정"은 반드시 전한다

```
⚠️ 하나만 미리 말씀드릴게요.
   주식 앱에서 "수익률"은 두 가지가 섞여서 자주 헷갈려요.
   · 평가손익 — 아직 안 판 것의 이익
   · 실현손익 — 실제로 팔아서 확정된 이익
   지금은 평가손익만 보여드릴게요. 실현손익은 거래 기록 화면에서 따로 볼 수 있게요.
```

**이런 게 리서치의 진짜 값어치다.** 나중에 "왜 숫자가 안 맞지?"를 미리 막는다.

## 5. 선택이 인수 조건이 된다

고른 선택지를 **AC로 옮긴다.** 사용자가 AC를 쓰는 게 아니라 **선택에서 자동으로 나온다.**

```
② 를 고르셨으니 이렇게 만들게요.

  AC-1  총 평가금액·평가손익·수익률이 맨 위에 보인다
  AC-2  1주/1달/3달/1년 을 눌러 기간을 바꿀 수 있다
  AC-3  그래프의 한 점을 누르면 그 시점 금액이 보인다
  AC-4  거래 기록이 없으면 "아직 거래가 없어요" 가 보인다
```

**AC가 5개를 넘으면 기능이 큰 것이다.** 쪼개자고 제안한다.
`devoffice gate spec` 이 기계적으로도 막는다.

## 6. "안 만드는 것"을 함께 적는다

구체화 단계에서 **거른 것들**이 여기로 간다. 이게 기대 차이를 미리 없앤다.

```
이번에 안 만드는 것
 · 종목별 수익률 (③에 있던 것 — 나중에 추가할 수 있어요)
 · 실현손익 (거래 기록 화면에서 볼 거예요)
 · 세금·수수료 반영 (백로그에 없어요. 필요하시면 말씀해주세요)
```

**여기 적힌 걸 만들면 나중에 범위 위반으로 잡힌다.**

## 8. 질문 예산은 여기서도 지킨다

구체화는 질문이 많아지기 쉽다. **응답을 요구하는 질문은 기능당 2개까지.**

- 화면 형태 선택 = 1개
- 정말 중요한 결정 = 1개
- 나머지는 **가정하고 통보한다** (🔵 이유와 함께)

> 3개 이상 물으면 사용자가 지쳐서 아무거나 고른다.
> **가장 비싼 두 개를 고르는 게 우리 일이다.**

## 하지 말 것

- 리서치 결과를 그대로 쏟기
- 스케치 없이 말로만 설명하기 — 비개발자는 상상 못 한다
- 사용자에게 먼저 묻지 않고 리서치부터 하기
- 사용자 안을 리서치 결과로 **대체**하기 (보완은 하되 덮지 마라)
- 선택지를 4개 이상 주기
- 색·폰트·여백을 여기서 정하기 — 디자인 시스템이 이미 잡혀 있다
- 조사에서 나온 **함정을 안 전하기** — 그게 가장 값진 부분이다
