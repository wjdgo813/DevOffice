# 우리 회사 규칙

> 모든 에이전트가 따른다. 이 규칙과 개별 지시가 충돌하면 **이 규칙이 이긴다.**
> 단, `.devoffice/product/playbook-<역할>.md` 가 있으면 그 플레이북이 우선한다.

---

## 1. 4대 불변 규칙

1. **시작 전에 지시서의 "먼저 읽을 파일"을 전부 읽는다.** 추측으로 시작하지 않는다
2. **작업 하나가 끝날 때마다 즉시** `devoffice task done <ID>` 를 실행한다. 몰아서 하지 않는다
3. **막히면 추측하지 않고 멈춘다.** `devoffice task block <ID> --type <종류>` 후 종료
4. **완료 보고서에 "하지 않은 것"과 "내 담당이 아닌 것 같은 것"을 반드시 채운다.**
   빈칸이면 "없음"이라고 명시한다

2번을 지키지 않으면 중간에 끊겼을 때 아무것도 남지 않는다.
4번을 지키지 않으면 아무도 안 만든 부분이 생긴다.

> **3번은 "구현 중 막힘"에 대한 규칙이다.**
> **사용자 환경에서 막히는 건 멈출 수 없다** — 원인을 찾아야 한다.
> 그때는 `${CLAUDE_PLUGIN_ROOT}/skills/_shared/diagnose.md` 를 따른다.
> 핵심만: **명령 한 줄로 확인되는 것부터 본다. 사용자에게 시켜보는 건 마지막이다.**

---

## 2. 무엇을 만들어도 되는가

| 분류 | 정의 | 조치 |
|---|---|---|
| **A** | 사용자가 요청한 것 | 만든다 |
| **B** | 요청하진 않았지만 **없으면 A가 성립하지 않는 것** | 만들되 **명세에 적고** 알린다 |
| **C** | **있으면 좋은 것** | **만들지 않는다.** 백로그에 제안만 |

**C가 가장 흔한 실수다.** "이왕 하는 김에"는 사용자가 모르는 코드를 늘리고,
검증 대상이 아니므로 아무도 확인하지 않는다.

`spec.md`의 **"이번에 안 만드는 것"에 적힌 걸 만들면 범위 위반**이다.

---

## 3. 한 번에 하나씩

- 기능 하나가 끝나고 **사용자가 눈으로 확인하기 전까지** 다음 기능을 시작하지 않는다
- 기능 하나가 크면 쪼갠다: **인수조건 5개 · 작업 8개 · 30분** 이 상한
- 상한을 넘으면 `devoffice gate` 가 막는다. 우회하지 말고 쪼갠다

`backend`와 `frontend`를 동시에 돌리는 것은 위반이 아니다 —
그건 "기능 여러 개"가 아니라 "기능 하나의 앞뒤면"이고, 계약이 경계를 잠근다.

---

## 4. 계약이 유일한 진실

- `packages/contracts/` 는 **cto만** 쓴다
- 서버와 화면은 **반드시 계약을 import** 해서 구현한다. 타입을 직접 다시 선언하지 않는다
- 계약이 틀렸다고 판단되면 **고치지 말고** 블로커를 발행한다

---

## 5. 파일 소유권

| 경로 | 소유자 |
|---|---|
| `packages/contracts/**` | cto 전용 |
| `supabase/**`, `**/api/**`, `server/**` | backend |
| `apps/web/**` (api 제외) | frontend |
| `apps/mobile/**` | frontend (별도 호출) |
| `.devoffice/**` | 프로듀서 · cto |

남의 경로를 고쳐야 한다면 그건 계획이 잘못된 것이다. 블로커를 발행한다.

---

## 6. 항상 빠지는 것들 — 매번 확인한다

- [ ] **로딩 / 빈 상태 / 에러 상태** 3종 세트
- [ ] 권한 없는 사용자가 접근했을 때
- [ ] 입력 검증 — **화면과 서버 양쪽** (한쪽만 하면 안 한 것과 같다)
- [ ] 데이터 구조를 바꿨으면 실제로 반영했는가
- [ ] 환경변수를 추가했으면 `.env.example` 갱신
- [ ] **기존 화면에서 이 기능으로 들어가는 경로** ← 가장 흔한 누락

마지막 항목 때문에 **모든 기능의 마지막 작업은 "진입 경로 연결"로 고정**한다.
기능을 만들었는데 거기로 가는 버튼이 없는 일이 압도적으로 자주 일어난다.

---

## 7. 비밀번호와 키

- API 키·비밀번호는 **`.env.local` 에만** 둔다. 코드에 그대로 쓰지 않는다
- 대화에 키를 그대로 남기지 않는다
- `.gitignore` 에 `.env*` 가 있는지 확인한다

훅이 막아주지만, 막히고 나서 고치는 것보다 처음부터 안 하는 게 낫다.

---

## 8. 언어

| 대상 | 언어 |
|---|---|
| 사용자에게 보이는 모든 것 | **한국어** |
| `.devoffice/` 문서 (사용자가 읽는다) | **한국어** |
| 코드·파일명·경로·식별자·커밋 메시지 | **영어** |

용어가 갈리지 않게 `.devoffice/product/glossary.md` 를 참조한다.
사용자는 "글"이라 하고 코드는 `post` 다 — 그 매핑이 거기 있다.
