# 어떻게 만들지 정한다

**사용자에게 묻는 건 딱 하나다: "사람들이 어디서 쓰나."**
나머지 기술 선택은 전부 우리가 정하고, 결과만 쉬운 말로 알린다.

---

## ① 웹이냐 앱이냐 — 유일한 질문

되돌리기가 가장 비싼 결정인데 **비개발자는 판단 근거가 없다.**
"앱이 더 좋은 거 아닌가?"라는 막연한 인상으로 고르면 이후 전부가 어려워진다.

**선택지에 이름이 아니라 결과를 쓴다.**

```
만드시는 걸 사람들이 어디서 쓰게 될까요?

 ① 웹사이트 (인터넷 주소로 접속)                      ← 추천
    · 링크만 보내면 바로 씀. 설치 없음
    · 검색에 나올 수 있음
    · 폰에서도 잘 보이게 만들어드려요

 ② 스마트폰 앱 (폰에 설치해서 씀)
    · 알림을 보낼 수 있음
    · 만드는 데 시간이 더 걸려요

 ③ 둘 다 (가장 오래 걸려요)

 ※ 잘 모르시겠으면 ①로 시작하는 걸 권해요. 나중에 앱으로도 만들 수 있어요.
```

**앱의 추가 부담은 고르기 전에 알린다.** 고른 뒤에 알리면 "이럴 줄 알았으면"이 된다.
단, **부담이 얼마인지는 "누가 쓰는가"에 따라 완전히 달라진다.** 아래를 먼저 판정한다.

### 앱을 고르면 — 비용은 사용 범위에 달렸다

**"앱 = 앱스토어 = 연 13만원"이 아니다.** 이렇게 안내하면 없는 비용을 물리게 된다.

| 쓸 사람 | 방법 | 비용 | 제약 |
|---|---|---|---|
| **본인(과 가족) 몇 명** | Xcode로 직접 설치 | **0원** | **7일마다 재설치**, 푸시 불가 |
| 〃 (Android) | APK 직접 설치 | **0원** | 없음 |
| 지인 여러 명 / 계속 쓸 것 | EAS Build | 연 $99 (iOS) | — |
| 불특정 다수 | 앱스토어 등록 | 연 $99 + 심사 1~2주 | — |

PRD에 **"본인 혼자"** 또는 소수만 쓴다고 되어 있으면 **첫 두 줄이 답이다.**
스토어와 개발자 계정을 꺼내지 마라.

이때 하나만 확인한다:

```
앱으로 만들 거면 하나만 여쭤볼게요.

  Xcode(애플이 만든 개발 프로그램)가 컴퓨터에 이미 깔려 있나요?

   ① 있어요                 그럼 폰에 바로 설치할 수 있어요. 돈 안 들어요.
   ② 없어요 / 모르겠어요     설치는 무료지만 용량이 커요(수십 GB).
                            대신 클라우드에서 만드는 방법도 있어요 (연 $99)
```

- **① → 로컬 빌드.** 무료 Apple ID면 충분하다. **7일마다 재설치**가 유일한 대가다
- **② → Expo Go로 먼저 써본다.** 계속 쓸 것 같으면 그때 둘 중 하나를 고른다

> **7일 만료를 반드시 미리 말한다.** 나중에 앱이 안 열리면 사용자는 고장인 줄 안다.

단톡방·메신저로 링크를 뿌릴 거라면 ①(웹)이 거의 항상 맞다. 그 점을 짚어준다.

| 답 | `stack.client` |
|---|---|
| ① | `web-next` |
| ② | `mobile-expo` |
| ③ | `both` |

## ② 서버가 필요한지는 우리가 판정한다

**"EC2를 쓸까요, Firebase를 쓸까요?"는 절대 묻지 않는다.**
PRD를 읽고 아래 신호를 찾는다.

| PRD에 이런 게 있으면 | 필요한 것 |
|---|---|
| 로그인·회원 | 인증 → BaaS로 충분 |
| 데이터 저장·공유, 사진 업로드 | DB·저장공간 → BaaS로 충분 |
| 채팅·알림 등 실시간 | realtime → BaaS로 충분 |
| 결제 | 서버 로직 → BaaS 함수로 대개 충분 |
| **정기 실행·수집·배치·무거운 연산** | **상시 서버 필요** |
| **사내망·특수 소프트웨어** | **VPS 필요** |

| 프리셋 | 대상 | 사용자 부담 |
|---|---|---|
| `baas-supabase` (기본) | 대부분 | 계정만 |
| `baas-firebase` | 실시간·모바일 푸시가 핵심 | 계정만 |
| `server-managed` | 상시 서버는 필요하나 관리는 싫다 | 계정 + 카드 |
| `server-lightsail` | "AWS를 쓰고 싶다" | 콘솔 클릭 ~5회 |
| `server-vps` | 사내망·완전한 제어 | 콘솔 클릭 ~10회 |

**기본은 `baas-supabase` 다.** 위로 올라가는 건 정말 필요할 때만이다.
"AWS를 쓰고 싶다"는 요구에 EC2를 주지 마라 — **Lightsail이 훨씬 나은 답**이다(고정 요금).

### 상시 서버가 필요하다고 판정되면

기술 선택이 아니라 **제품 트레이드오프로 번역해서** 묻는다.

```
만드시려는 기능 중 [매일 새벽 자동 수집]이 있어서,
항상 켜져 있는 서버가 필요해요.

 ① 서버를 두고 그 기능을 넣는다      설정 30분 추가, 월 ○원쯤
 ② 그 기능만 빼고 나머지를 먼저 만든다  설정이 훨씬 간단해요. 나중에 추가할 수 있어요  ← 추천

👉 어느 쪽으로 할까요?
```

## ③ 무료 한도는 제품 언어로 환산해서 알린다

"1GB", "월 50,000 요청"은 비개발자에게 아무 의미가 없다.

| 기술 한도 | 이렇게 말한다 |
|---|---|
| 저장공간 1GB | 사진 약 1,000장 |
| DB 500MB | 글 약 50,000개 |
| 월 100,000 요청 | 월 방문 약 3,000명 |
| 대역폭 100GB | 월 방문 약 10,000명 |

```
두 가지만 알려드릴게요.

  · 사진을 올리는 기능이 있어서 저장 공간이 필요한데,
    무료로 사진 약 1,000장까지 돼요. 80% 차면 미리 알려드릴게요.
  · 서버를 따로 두지 않아도 되는 구조라 관리하실 게 없어요.
```

## 스택 기본값 (v0.1)

사용자에게 묻지 않는다. 이유는 **선택지를 줄이면 실패도 준다**는 것 하나다.

| 층 | web-next | mobile-expo |
|---|---|---|
| 화면 | Next.js (App Router) + TypeScript | Expo + TypeScript |
| 스타일 | Tailwind + shadcn/ui | NativeWind |
| 데이터·인증 | Supabase | Supabase |
| 배포 | Vercel | Expo Go → EAS |

**디자이너 에이전트를 두지 않는 이유:** 디자인 시스템을 여기서 한 번 잠그면
이후 화면의 80%가 자동으로 일관된다. 매 기능마다 부르는 것보다 싸고 결과가 낫다.

## 하지 말 것

- 프레임워크 이름을 사용자에게 묻기
- 선택지를 이름만 나열하기 (결과를 함께)
- 앱의 추가 부담을 고른 뒤에 알리기
- "확장성", "러닝커브" 같은 말 쓰기
- 잠근 뒤에 가볍게 바꾸기 — 바꾸려면 처음부터 다시 만들어야 한다
