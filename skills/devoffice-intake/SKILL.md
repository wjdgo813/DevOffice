# 인테이크 — 무엇을 만들고 싶은가

**목표:** 대화 5~10분으로 PRD를 쓸 수 있을 만큼 알아낸다.
체크리스트를 순서대로 물으면 취조가 된다. 실제 PM이 쓰는 순서를 따른다.

---

## 첫 질문은 좁게 던진다

"어떤 걸 만들고 싶으세요?"는 너무 열려서 비개발자가 답을 못 한다.
**한 문장으로 좁히고 예시를 3개 준다.**

```
어떤 걸 만들고 싶으세요? 한 문장이면 충분해요.

  예) "동네 사람들끼리 물건 빌려주는 사이트"
      "우리 동아리 일정 관리하는 앱"
      "내 그림 모아서 보여주는 페이지"

👉 편하게 말씀해주세요
```

---

## 그다음 — 비개발자가 가장 잘 답할 수 있는 순서로

한 번에 하나씩 묻는다. 두 개 이상 묶어 묻지 않는다.

### ① 레퍼런스 — 가장 강력한 질문

> "비슷한 서비스가 있을까요? 있으면 이해가 훨씬 빨라요."

**"당근마켓 같은 건데 우리 아파트만"** 한 문장이 명세 100줄보다 정확하다.

답이 나오면 **닮은 점과 다른 점을 갈라 묻는다.** 객관식으로.

```
당근마켓에서 어떤 부분이 비슷한가요? (여러 개 고르셔도 돼요)

  ① 사진이랑 설명 올리는 것      ② 목록에서 골라 보는 것
  ③ 채팅으로 연락하는 것         ④ 동네 인증
  ⑤ 거래 후기

반대로 없어도 되는 건 뭘까요?
```

**"없어도 되는 것"을 반드시 묻는다.** 사용자는 원하는 건 말하지만
원하지 않는 건 말하지 않는다. 이게 범위 착각을 잡는 유일한 방법이다.

레퍼런스가 없다고 하면 **우리가 후보를 제시하고 고르게 한다.** 빈칸을 주지 않는다.

### ② 지금은 어떻게 하고 있나

> "지금은 어떻게 하고 계세요?"

**"단톡방에 사진 올려요" / "엑셀로 관리해요"** 안에 요구사항이 다 들어있다.

엑셀·노션·메모가 있다고 하면 **달라고 한다.**
말로 설명하게 하는 것보다 이미 있는 것을 읽는 게 압도적으로 정확하다.

> "그 엑셀 파일 이 창에 끌어다 놓으실 수 있을까요? 보면 훨씬 정확해져요."

### ③ 누가 쓰나

> "누가 쓰게 될까요? 몇 명쯤 될 것 같으세요?"

규모가 나중에 기술 선택을 가른다. 하지만 그 이유를 사용자에게 설명하지 않는다.

### ④ 뭐가 제일 불편한가

> "지금 제일 불편한 게 뭐예요?"

해결책이 아니라 **문제**를 듣는다. 사용자가 해결책을 말하면 한 번 거슬러 올라간다.

---

## 놓치기 쉬운 것 — 한 번은 묻는다

비개발자는 **어려울까봐 미리 포기하고 말하지 않는다.**

> "혹시 원래 생각하셨던 게 더 있는데, 어려울까봐 말씀 안 하신 건 없나요?"

이 질문 하나로 진짜 원했던 기능이 나오는 경우가 많다.
나오면 타당성을 판단하고(§타당성), 가능하면 백로그에 넣는다.

---

## 타당성 — 지금 3색으로 나눈다

기능이 언급되는 **즉시** 분류한다. 조사는 아직 하지 않는다.

| 색 | 기준 | 예 |
|---|---|---|
| 🟢 | 표준 기능. 외부 의존 없음 | 로그인, 글쓰기, 목록, 검색, 좋아요 |
| 🟡 | 외부 서비스 의존 | 결제, 지도, 소셜 로그인, 이메일 발송, 푸시 |
| 🔴 | **데이터·법적·기술적 불확실** | 특정 데이터 확보, 크롤링, AI 모델, 실시간 대용량 |

**🔴가 있으면 여기서 멈추고 `devoffice-research`로 조사한다.**
제품의 핵심 전제가 성립하지 않는데 계속 진행하면 나중에 전부 낭비가 된다.

> "말씀하신 것 중에 [○○] 부분은 데이터를 구할 수 있는지 먼저 확인해봐야 해요.
>  5분만 알아보고 올게요. **화면이 조용해도 정상이에요.**"

🟡는 기록만 해두고 백로그 확정 전에 조사한다.

## 마무리

충분히 들었으면 정리해서 되말한다. 그리고 이름으로 넘어간다.

```bash
devoffice state set product.oneLiner "<한 줄 정의>"
devoffice state set phase NAMING
```

그다음 `devoffice-naming` 스킬로 넘어간다.

## 하지 말 것

- 한 번에 여러 개 묻기 — 비개발자는 마지막 질문만 답한다
- "타겟 유저는요?" 같은 업계 용어
- 기술 이야기 (어떤 언어로, 어디에 올릴지) — 그건 우리가 정한다
- 아이디어 평가하기. **"그건 어렵겠는데요"라고 먼저 말하지 않는다.**
  타당성은 조사로 판단하고, 안 되면 **대안과 함께** 말한다
