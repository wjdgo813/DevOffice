# 제품 정의서

**목표:** 무엇을 만들지 서로 같은 그림을 갖는다.

---

## 첫 번째 함정 — 문서를 통째로 승인받지 않는다

문서를 다 보여주고 "확인해주세요"라고 하면 **사용자는 안 읽고 "네"라고 한다.**
그리고 나중에 "이건 제가 원한 게 아닌데요"가 된다.

> **문서는 쓰되, 승인은 요약 3가지로 받는다.**

---

## ① 문서를 쓴다

`.devoffice/product/prd.md` 에 쓴다. 사용자 언어로, 기술 용어 없이.

```markdown
# <제품 이름>

## 한 줄로 말하면
## 누가 쓰나
## 무엇을 할 수 있나
## 이번에 안 하는 것        ← 중요. 범위 경계
## 아직 확인이 필요한 것    ← 🟡🔴 타당성 미확인 항목
```

같은 개념을 매번 다르게 부르지 않도록 `.devoffice/product/glossary.md` 도 함께 시작한다.

| 사용자 표현 | 우리 개념 | 정의 |
|---|---|---|
| 물건, 나눔글 | item | 사용자가 올리는 나눔 대상 |

---

## ② 요약 3가지로 확인받는다

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  동네나눔
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

이렇게 이해했어요. 3가지만 확인해주세요.

 1. 이런 서비스예요
    같은 아파트 사람들끼리 안 쓰는 물건을 나누는 사이트

 2. 이런 분들이 써요
    같은 단지 주민. 처음엔 수십 명 정도

 3. 이런 걸 할 수 있어요
    · 물건을 올린다        · 올라온 물건을 본다
    · 가져가고 싶다고 한다  · 나눔 후 후기를 남긴다

  채팅은 안 넣어요 (단톡방 쓰신다고 하셔서)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
👉 맞으면 "네", 다르면 어디가 다른지 말씀해주세요
   ※ 나중에 얼마든지 바꿀 수 있어요
```

- **"안 넣는 것"을 반드시 한 줄 넣는다.** 기대와 결과의 차이를 미리 없앤다
- **"나중에 바꿀 수 있어요"를 빠뜨리지 마라.** 없으면 사용자는 최악을 가정하고 얼어붙는다
- 전체 문서는 볼 수 있게만 해두고 **읽으라고 요구하지 않는다**

---

## ③ 승인 직후 — 전체 흐름을 한 번 보여준다

**여기가 지도를 보여주기에 가장 좋은 시점이다.** 무엇을 만들지 정해졌으니
이제 "어떻게 진행되는지"가 궁금해진다. 그리고 이걸 지금 안 보여주면
사용자는 매 단계마다 "이게 뭐 하는 거지?"를 안고 간다.

```
좋아요. 앞으로 이렇게 진행돼요.

  ✅ 1. 무엇을 만들지 정하기      ← 방금 끝났어요
     2. 어떻게 만들지 정하기      웹인지 앱인지, 서버가 필요한지
     3. 준비물 갖추기            계정 만들기
     4. 빈 화면 띄워보기          기능 없이 껍데기만. 잘 열리는지 확인
     5. 만들 기능 정하기          9가지를 어떤 순서로 만들지
     6. 기능 하나씩 만들기        ← 여기가 대부분의 시간이에요

  1~5는 오늘 안에 끝나요. 6번부터가 진짜 만드는 시간이에요.
```

**"6번이 대부분"이라고 미리 말하는 게 중요하다.**
안 그러면 1~5를 지나며 "언제 만드나" 조급해진다.

### 기대 관리

**이 말을 하지 않으면 3일째에 "왜 이렇게 오래 걸리지"가 된다.**

```
  기능은 9개 정도 될 것 같아요. 하나에 20~30분씩 걸리니까
  하루 2~3개씩 하시면 일주일 정도예요.
  한 번에 다 하실 필요 없고, 언제든 멈췄다 이어서 하시면 돼요.
```

---

## ④ 준비물을 미리 알린다

**"다 만들었는데 넣을 내용이 없다"가 실제로 가장 자주 막는다.**
쇼핑몰을 만들었는데 상품 정보가 없고, 블로그를 만들었는데 쓸 글이 없다.

```
  그리고 미리 알려드릴 게 하나 있어요.
  나중에 물건 사진이 필요해요. 지금 없어도 괜찮고,
  없으면 제가 예시 사진으로 채워둘게요.
```

로고·소개 문구도 같은 방식으로 미리 알린다. **없어도 진행된다는 점**을 함께 말한다.

## 사용자가 "다르다"고 할 때

고맙게 받는다. **여기서 잡는 게 가장 싸다.**

세 번째 수정이면 잘못 이해한 것이므로 되돌아가 다시 묻는다
(`_shared/dialogue.md` §10).
