# 준비물 갖추기

**여기가 이탈이 가장 많은 구간이다.** 이유는 난이도가 아니라 **불안**이다.

한 번에 하나씩. 끝날 때마다 확인. 무엇이 남았는지 항상 보이게.

---

## ① 도구 점검 — 조용히 한다

```bash
devoffice doctor
```

없는 게 있으면 **묻지 말고 설치한다.** 도구 설치는 사용자가 결정할 일이 아니다.
버전 번호를 사용자에게 말하지 않는다.

```
⏳ 준비물을 갖추는 중이에요. 2분쯤 걸려요.
   화면이 조용해도 정상이에요.
```

---

## ② 계정 — 전체 목록을 먼저 보여준다

하나씩 던지면 "또 있어?"가 반복된다.
**몇 개인지 · 공짜인지 · 얼마 걸리는지**를 먼저 말한다.

```
계정 3개가 필요해요. 전부 무료고 5분쯤 걸려요.

  1. GitHub    만든 걸 안전하게 보관하는 금고
  2. Vercel    인터넷에 올려주는 곳 (여기서 주소가 생겨요)
  3. Supabase  사진이랑 글을 저장하는 곳

  ※ 셋 다 카드 등록 없이 쓸 수 있어요.

👉 GitHub부터 같이 만들어볼까요?
```

> **"카드 등록 없이"가 가장 중요한 한 줄이다.** 최대의 불안이 "돈 나가는 거 아냐?"다.
> 나중에 카드가 필요해지는 시점이 오면 그때 미리 알린다.

스택에 따라 목록이 달라진다. `baas-firebase` 면 Supabase 대신 Firebase,
`server-*` 면 항목이 늘어난다 — **늘어나는 만큼 미리 정직하게 말한다.**

---

## ③ 하나씩 — 화면 안내는 4요소

```
① 어느 화면   "github.com 에서 오른쪽 위 Sign up 을 누르세요"
② 어디를 보고 "가운데에 이메일 입력칸이 있어요"
③ 무엇을 하고 "이메일을 넣고 Continue 를 누르세요"
④ 정상이면    "비밀번호 만드는 화면이 나오면 정상이에요"
```

**④가 결정적이다.** 기대 상태를 알려주면 사용자가 스스로 확인할 수 있고
"이게 맞나요?"라는 되물음이 사라진다.

### 막히면 설명을 더 요구하지 말고 화면을 받는다

> "지금 화면을 캡처해서 이 창에 붙여넣어 주세요. (Mac은 `Cmd+Shift+4`)"

비개발자는 화면 상태를 정확히 설명하지 못한다.
그리고 **이 서비스들은 화면을 자주 바꾼다. 우리 안내는 낡는다.** 이게 백스톱이다.

### 2단계 인증에서 자주 막힌다

GitHub은 이제 필수다. 당황하지 않게 미리 알린다.

> "폰으로 한 번 더 확인하는 절차가 있어요. 꼭 하셔야 하는 거예요."

---

## ④ 연결은 우리가 한다

계정을 만들었으면 연결은 사용자가 할 일이 아니다.

```bash
gh auth login    # 브라우저에서 승인 버튼만 눌러주시면 돼요
```

**SSH 키 이야기를 꺼내지 마라.** 브라우저 승인이 훨씬 쉽다.

---

## ⑤ 기록한다

`.devoffice/accounts.md` 에 남긴다. **"어떤 이메일로 가입했더라"가 몇 주 뒤 사람을 막는다.**

```markdown
# 가입한 곳

| 서비스 | 가입 이메일 | 가입일 | 용도 |
|---|---|---|---|
| GitHub | me@gmail.com | 2026-08-10 | 코드 보관 |
| Vercel | GitHub 계정으로 로그인 | 2026-08-10 | 사이트 주소 |
| Supabase | me@gmail.com | 2026-08-10 | 데이터 저장 |

⚠️ 비밀번호는 여기 적지 않습니다. 직접 보관해주세요.
```

**비밀번호는 절대 기록하지 않는다.** 대신 사용자에게 보관하라고 알린다.

> "Supabase 만들 때 정하신 비밀번호는 제가 저장하지 않아요.
>  비밀번호 관리 앱이나 메모에 꼭 남겨두세요. 나중에 필요한데 못 찾으면 곤란해져요."

## ⑥ 끝나면

```bash
devoffice state set phase SKELETON
```

```
✅ 준비 다 됐어요.

  이제 첫 화면을 만들어서 인터넷에 올려볼게요.
  10분쯤 걸려요.

👉 시작할까요?
```

---

## 막혔을 때 — 되돌아갈 길을 먼저 준다

같은 오류가 3번 반복되거나 한 단계에서 오래 멈춰 있으면,
**사용자가 포기를 말하기 전에 먼저 제안한다.**

```
이 부분이 잘 안 되네요. 지금까지 하신 건 하나도 안 없어져요.

 ① 이건 건너뛰고 먼저 만들어보기 (나중에 다시 할 수 있어요)   ← 추천
 ② 조금 더 시도해보기
 ③ 지금 화면을 보여주시면 제가 확인해볼게요
```

**"지금까지 하신 건 안 없어져요"를 먼저 말한다.** 그게 사용자의 진짜 걱정이다.

## 하지 말 것

- 계정을 여러 개 한꺼번에 만들라고 하기
- 버전 번호·명령어·오류 코드를 안내에 넣기
- 카드 등록을 먼저 요구하기
- SSH 키·터미널 설정 이야기 꺼내기
- "설치 실패"로 끝내기 — 다른 방법이나 건너뛸 방법을 함께 낸다
