# 만들 기능 정하기

**여기서는 목록과 순서만 정한다. 기능을 구체화하지 않는다.**

9개를 한꺼번에 구체화하면 사용자가 압도되고, 그렇게 정한 것의 절반은
막상 만들 때 바뀐다. **구체화는 그 기능을 만들기 직전에 한다**(`devoffice-spec`).

여기서 하는 일은 **"무엇을, 어떤 순서로"** 딱 둘이다.

---

## ① PRD의 기능을 늘어놓는다

기능 이름이 아니라 **"~할 수 있어요"** 사용자 문장으로 쓴다.
`ItemService`, `잔액조회API` 같은 건 사용자에게 아무 의미가 없다.

---

## ② 순서를 정한다 — 의존성이 먼저, 그 안에서 가시성

두 가지가 충돌한다.

- **의존성**: 담을 게 있어야 전략을 붙인다 → 종목이 먼저
- **가시성**: 눈에 보이는 게 먼저여야 성취감이 생긴다

> **규칙: 1번은 "의존성이 없으면서 가장 눈에 보이는 것"으로 고른다.**
> 후보가 없으면, 의존성 있는 기능을 **눈에 보이는 조각으로 쪼개서** 1번으로 만든다.
> (예: "로그인" 대신 "로그인 화면이 생긴다")

**순서마다 이유를 한 줄 붙인다.** 이유가 없으면 사용자는 "왜 이게 먼저지?"를 안고 간다.

### 연결(`dependsOn`)을 반드시 기록한다 ★

순서를 정했다는 건 **무엇이 무엇에 기대는지 이미 판단했다**는 뜻이다. 그 판단을 버리지 마라.

```json
{"id":"F-004","title":"종목에 전략을 붙여요","dependsOn":["F-001","F-003"]}
```

**이걸 안 남기면 나중에 사용자가 "이 기능 빼주세요"라고 할 때
무엇이 같이 무너지는지 알 수 없다.** 그리고 "영향 없음"이라고 잘못 답하게 된다.

`devoffice backlog list` 로 확인한다 — 연결이 비어 있으면 경고가 나온다.

---

## ③ 타당성을 3색으로 나눈다

기능이 목록에 오르는 **즉시** 색을 매긴다.

| 색 | 기준 | 조치 |
|---|---|---|
| 🟢 | 표준 기능. 외부 의존 없음 | 그냥 진행 |
| 🟡 | 외부 서비스·데이터 의존 | 백로그 확정 **전에** 조사 |
| 🔴 | 데이터·법적·기술적 불확실 | **지금 조사.** 안 되면 목록에서 빼거나 대안 |

Formula-Q 라면 "종목을 찾는다"는 🟡이다 — 한국투자증권에서 종목 목록을
받아올 수 있어야 한다. **확정하고 2주 뒤에 안 된다는 걸 알면 그때까지가 낭비다.**

🟡🔴은 `research` 에이전트에게 **한 번에 모아서** 보낸다. 하나씩 보내면 오래 걸린다.

```
⚠️ 세 가지는 먼저 확인이 필요해요.
   종목 검색 · 실시간 시세 · 자동 주문 — 증권사에서 되는지 알아볼게요.
   5분쯤 걸려요. 화면이 조용해도 정상이에요.
```

---

## ④ 크기를 미리 본다

**한 기능이 30분을 넘을 것 같으면 여기서 쪼갠다.**
나중에 명세 단계에서 쪼개면 사용자가 "아까 9개라더니?"라고 느낀다.

쪼갤 때는 알린다.

> "'전략 만들기'는 좀 커요. 둘로 나눌게요 —
>  ① 준비된 전략 중에 고르기 ② 내가 직접 만들기"

---

## ⑤ 보여주고 확인받는다

**처음 3개만 펼치고 나머지는 접는다.** 9개를 한꺼번에 보면 압도된다.

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  만들 기능 정하기                 5/6
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

이 순서로 만들면 좋을 것 같아요. 총 9개, 일주일쯤이에요.

 1. 종목을 찾아서 담을 수 있어요    먼저. 담을 게 있어야 전략을 붙여요
 2. 담은 종목을 목록으로 봐요       담은 게 보여야 다음 단계가 돼요
 3. 준비된 전략 중에 고를 수 있어요

 ... 나머지 6개 (자세히 보고 싶으시면 말씀해주세요)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
👉 이 순서 괜찮으세요? 빠진 게 있나요?
   ※ 순서는 나중에 바꿔도 돼요
```

> **"빠진 게 있나요?"를 반드시 묻는다.**
> 사용자는 목록에 **없는 것**을 스스로 알아채지 못한다.
> 이름이 달라서 "있는 줄 알았다"가 가장 흔하다.

새 기능이 나오면 **즉시 3색을 매기고** 순서에 끼워 넣는다.

---

## ⑥ 저장한다

```bash
devoffice state set backlog '[{"id":"F-001","title":"종목을 찾아서 담기","status":"pending"}, ...]'
devoffice state set phase FEATURE_LOOP
```

**저장되는 순간부터 진척도가 진짜 숫자가 된다.** 그전까지는 진척도가 없다 —
없는 숫자를 만들어내지 마라.

---

## ⑦ 닫고 다음으로

```
✅ 5단계 끝났어요. 만들 순서가 정해졌어요.

   이제부터는 이 순서대로 하나씩 만들어요.
   기능 하나를 만들 때마다 폰에서 직접 확인하시게 돼요.

   ⚠️ 지금은 "무엇을" 만들지만 정했어요.
      "어떻게 보일지"는 각 기능을 만들기 직전에 같이 정해요.
      한꺼번에 정하면 너무 많고, 어차피 만들면서 바뀌거든요.

👉 1번 "종목을 찾아서 담기" 부터 시작할까요?
```

**마지막 경고가 중요하다.** 안 그러면 사용자는 "화면 이야기는 언제 하지?"를 안고 간다.

- 여기서 기능을 구체화하기 (화면·필드·동작) — 그건 `devoffice-spec` 이다
- 9개를 한꺼번에 펼쳐 보여주기
- 순서 이유를 생략하기
- "빠진 게 있나요?"를 건너뛰기
- 타당성 확인 없이 🟡🔴을 목록에 확정하기
