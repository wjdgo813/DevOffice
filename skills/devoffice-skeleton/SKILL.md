# 첫 화면을 인터넷에 올린다

**이 단계가 제품의 성패를 가른다.**
사용자가 "내 사이트가 생겼다"를 경험하는 순간이고, 여기를 넘기면 이탈이 급감한다.

기능은 아직 하나도 없다. 그래도 **배포까지 간다.**
배포 파이프라인은 나중에 붙일수록 비싸지고, 기능이 0개일 때 뚫는 게 가장 싸다.

---

## ① 무엇이 아닌지부터 말한다

**이 단계 이름을 "첫 화면 만들기"라고 부르지 마라.**
사용자는 기능이 든 화면을 상상하고, "아직 아무것도 안 정했는데 벌써?"라고 불안해한다.

시작 전에 반드시 이 셋을 말한다.

```
👉 이제 빈 앱을 폰에 띄워볼게요. 15분쯤 걸려요.

   ① 무엇을 하나    이름만 뜨는 껍데기를 만들어서 폰에서 열리는지 확인해요
   ② 무엇이 아닌가  기능은 아직 안 들어가요. 종목도 전략도 다음 단계예요
   ③ 왜 지금 하나   나중에 하면 어디가 잘못됐는지 찾기 어려워져서,
                    아무것도 없을 때 길을 먼저 뚫어두는 거예요

   중간에 화면이 조용해도 정상이에요.
   (제가 하는 중이어도 언제든 끼어들어 말씀하셔도 돼요. 하던 건 안 없어져요.)
```

**③이 있어야 사용자가 이 단계를 건너뛰자고 하지 않는다.**
"왜 기능부터 안 만들고 빈 화면을?"은 자연스러운 의문이다. 먼저 답해준다.

세션에서 처음 오래 기다리게 하는 순간이므로, 괄호 안의 말도 여기서 한 번 한다.

## ② 골격을 만든다

`stack.client` 에 따라 갈린다.

### web-next

```bash
npx create-next-app@latest . --ts --tailwind --app --eslint --src-dir=false --import-alias="@/*" --use-npm --yes
devoffice scaffold web-next
```

`create-next-app` 이 만든 위에 우리 것을 덧씌운다.
**Next.js 원본을 우리가 들고 있지 않는 이유**는 프레임워크가 빨리 바뀌기 때문이다.

### mobile-expo

> ⛔ **`create-expo-app@latest` 를 그냥 쓰지 마라.**
> 최신 SDK로 만들어지는데, 폰에 깔리는 Expo Go 는 **App Store 심사 때문에 항상 뒤처진다.**
> 그러면 **폰에서 절대 안 열린다.** 사고가 아니라 상시 조건이다.
> (실제로 겪었다 — SDK 57로 만들었는데 스토어 Expo Go 는 54였다)

**만들기 전에 반드시 확인한다.** 5초면 된다.

```bash
devoffice expo check
```

출력이 알려주는 SDK를 **그대로 박아서** 만든다.

```bash
npx create-expo-app@latest . --template blank-typescript@sdk-54   # ← check 가 준 번호
devoffice scaffold mobile-expo
```

`expo check` 가 인터넷 문제로 확인에 실패하면 **최신으로 밀어붙이지 말고 멈춘다.**
확인 못 한 채 만들면 폰에서 안 열리고, 원인 찾느라 사용자가 네 번 헛걸음한다.

**화면 하나짜리로 시작한다.** `expo-router`·NativeWind는 지금 붙이지 않는다 —
화면 구성을 아직 모르는데 미리 정하면 나중에 다시 뜯는다.
화면이 둘 이상 되는 첫 기능에서 라우터를 넣는다.

**폰에 올리는 방법은 세 가지고, 상황에 따라 다르다.**

| 방법 | 언제 | 필요한 것 |
|---|---|---|
| **Expo Go** | 처음 확인할 때. 가장 빠르다 | 폰에 Expo Go 앱만 |
| **로컬 빌드** | 진짜 앱처럼 계속 쓸 때 | Xcode + 무료 Apple ID. **7일마다 재설치** |
| **EAS Build** | Xcode가 없거나 남에게 줄 때 | 개발자 계정 연 $99 |

v0.1에서는 **Expo Go로 먼저 띄운다.** 가장 빠르고 아무것도 안 든다.

```bash
npx expo start --tunnel
```

**터널로 띄운다.** 같은 와이파이를 전제하면 방화벽·게스트망·회사망에서 막히고,
그때 원인이 안 보인다. 터널은 조금 느리지만 **어디서든 열린다.**

### 안내하기 전에 반드시 확인한다

```bash
devoffice expo status
```

**`개발 서버 켜져 있음` 이 나오기 전에는 사용자에게 아무것도 안내하지 않는다.**
백그라운드 명령은 조용히 죽는다. 죽은 서버를 두고 "폰으로 열어보세요"라고 하면
사용자만 헛걸음하고, 원인이 폰에 있는 것처럼 보이게 된다.

### 안내

```
🔗 폰으로 확인해보세요

  1. 폰 App Store 에서 "Expo Go" 를 받으세요 (무료)
  2. 폰의 기본 카메라 앱을 켜세요   ← Expo Go 말고 카메라예요
  3. 컴퓨터 화면의 QR 코드를 비추세요
  4. 위에 뜨는 알림 띠를 누르세요
     → 파란 막대가 차오르다가 {{제품이름}} 이 뜨면 정상이에요 (처음엔 30초쯤)
```

> **"Enter URL manually" 를 안내하지 마라.** Expo Go 최신 버전에서 없어졌다.
> **카메라로 QR 을 찍는 것이 정식 방법이다.**
> 화면 구성은 버전마다 바뀌므로, 안 보인다고 하면 **캡처를 받아서 확인한다.**

### 안 열린다고 하면

**다른 걸 시도하기 전에 이것부터 실행한다.**

```bash
devoffice expo status
```

서버 상태 · 우리가 만든 SDK · 폰이 받을 수 있는 SDK 를 한 번에 보여준다.
버전이 어긋나 있으면 **폰이 아니라 우리 쪽을 맞춘다.**

절차 전체는 `${CLAUDE_PLUGIN_ROOT}/skills/_shared/diagnose.md` 를 따른다.
요약하면 — **명령으로 확인되는 것부터 보고, 사용자에게 시켜보는 건 마지막이다.**

확인이 끝나면 **진짜 앱으로 설치하는 법**을 이어서 안내한다(Xcode가 있는 경우).

```bash
npx expo prebuild
npx expo run:ios
```

> **7일 만료를 반드시 미리 말한다.**
> "일주일쯤 뒤에 앱이 안 열릴 거예요. 고장 아니고 원래 그런 거예요.
>  그때 다시 설치해드릴게요. 매주가 번거로워지시면 다른 방법도 있어요."
>
> 안 알려주면 사용자는 **고장인 줄 알고 떠난다.**

## ③ 기반 설비를 함께 넣는다 — 그리고 반드시 알린다

지금 넣으면 공짜지만 나중에 붙이려면 손이 많이 간다.
**사용자가 요청하지 않은 것이므로 만들었으면 말한다.**

```
만들면서 두 가지를 같이 넣어둘게요.

  · 오류가 나면 저한테 알려주는 장치
    (누가 쓰다가 문제를 만나도 저희가 알 수 있어요)
  · 나중에 쓰시는 분들이 문의할 수 있는 버튼

  지금 넣어두면 공짜인데, 나중에 붙이려면 손이 많이 가서요.
```

v0.1에서는 **최소한만** 넣는다. 화면 구석 문의 링크와 오류 기록 자리만.
정교한 수집 도구는 v0.3이다.

## ⑤ 보여준다 — 이 순간이 핵심이다

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🎉 주소가 생겼어요!
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  🔗 https://dongne-nanum-8x2p.vercel.app

  열어보시면 "동네나눔에 오신 걸 환영합니다"가 보일 거예요.

  주소 뒤에 붙은 이상한 글자는 원래 그런 거예요.
  나중에 원하시면 예쁜 주소를 따로 살 수도 있어요. (연 1~2만원)

  지금은 이 한 줄뿐이지만, 앞으로 만드는 기능이
  전부 이 주소에 바로 올라가요.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔗 한번 열어보고 오세요
```

세 가지를 빠뜨리지 않는다:

1. **주소 뒤 임의 문자열을 미리 설명한다.** 안 하면 "왜 이런 이상한 주소예요?"가 된다
2. **"앞으로 만드는 게 전부 여기 올라간다"** — 지금 이게 왜 중요한지
3. **직접 열어보게 한다.** 말로 듣는 것과 자기 화면에서 보는 것은 다르다

## ⑥ 닫고 다음으로

```bash
devoffice state set phase BACKLOG
```

**단계를 닫고, 다음이 무엇인지 정확히 말한다.**

```
✅ 4단계 끝났어요. 만든 게 실제로 열린다는 걸 확인했어요.

   여기까지 정해진 것
    · 무엇을 만들지 · 이름 · 웹인지 앱인지 · 서버 필요 여부

   아직 안 정한 것
    · 어떤 기능을 어떤 순서로 만들지   ← 이게 다음 단계예요

👉 이제 5단계, 만들 기능 목록을 정해볼까요? (10분쯤)
   PRD에 적어둔 9가지를 순서대로 늘어놓고, 빠진 게 없는지 같이 볼 거예요.
   여기서도 아직 만들지는 않아요.
```

**"여기서도 아직 만들지는 않아요"를 빠뜨리지 마라.**
4단계에서 뭔가 만들어졌으니 5단계도 만드는 줄 안다.

## 막혔을 때

배포는 계정 상태·권한 때문에 막히는 일이 흔하다. **되돌아갈 길을 먼저 준다.**

```
올리는 데서 막히네요. 만든 건 그대로 있어요.

 ① 제 컴퓨터에서 먼저 열어보기 (주소는 나중에)     ← 추천
 ② 다시 시도해보기
 ③ 지금 화면을 보여주시면 확인해볼게요
```

로컬에서라도 화면이 뜨면 사용자는 "만들어지고 있다"를 본다.
**아무것도 못 보고 끝나는 것이 최악이다.**

## 하지 말 것

- **"Hello World"를 화면에 쓰기.** 기대와의 낙차로 첫 성공 경험이 실망이 된다
- 배포를 건너뛰고 로컬에서만 확인하기 (정말 막혔을 때만 예외)
- 터미널 출력을 사용자에게 그대로 보여주기
- 도메인 구입을 지금 권하기 — 기본 주소로 충분하고, 예쁜 주소는 S9에서
- 기능을 하나라도 미리 만들기. **여기서는 첫 화면만 올린다**
